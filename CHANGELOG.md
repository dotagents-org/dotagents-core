# Changelog

What changed for someone who updates a clone. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). `dotagents update` names the version change after a pull.

## Unreleased

### Breaking

- **No pages and no VS Code extension here:** `dotagents start` is the accounts' local API only (`/api/`), and the panel, the avatars, the status bar and the switch in VS Code moved to [dotagents-sidebar](https://github.com/dotagents-org/dotagents-sidebar) 0.8.0, as its first tab. Uninstall the `dotagents-accounts` extension and install the sidebar. The page in the browser is gone.
- **The API carries its version:** every answer and event of `dotagents start` has `"apiVersion": 1`; a read that fails answers its error instead of stopping the server, and a second `start` leaves the running one alone.
- **The configuration left the repository:** dotagents-core is the tool only. Your configuration is a repository of its own, `dotagents-config`, cloned next to it (`dotagents/dotagents-core` and `dotagents/dotagents-config`); `config/` inside a fork and `DOTAGENTS_CONFIG` still work, in that order after the variable. `templates/config/` is a generic one to start from. The skills dotagents itself uses, `session-archive` and `move-sessions`, moved to `skills/` here; one of yours with the same name wins. After pulling, move your `config/` into its own repository next to the clone, then run `dotagents install` and `dotagents update --all`, which relink `~/.claude` and every workspace's skills.
- **The configuration moved into `config/`:** `global/`, `rules/`, `claude/`, `skills/` and the accounts' icons (`assets/claude-*`) now live in `config/`, apart from the tool; `DOTAGENTS_CONFIG` points the command at a folder of your own instead. After pulling, run `dotagents install` and `dotagents update --all`, which relink `~/.claude/rules`, the settings and every workspace's skills.
- **No more full-screen view.** dotagents is a plain command line, for people and for agents; the visual side moves to a separate app, still to come. `dotagents` with no command prints the help, `usage --watch` stops with a message, and Ink and React are no longer dependencies.
- **`usage --json` prints an envelope:** `{ "version": 1, "generatedAt": …, "profiles": [ … ] }` instead of a bare list, so new fields never break a script again.
- **`usage --short` changed format** for status lines: one line per profile, `5h` and `7d` with 8-cell bars (`work  5h ━━━━━━ ─  72% ↻ 3h17m   7d …`).
- **Node 22.18 or later.** The sources are TypeScript, run directly through Node's type stripping, with no build.
- **The command's entry file is `cli.ts`, no longer `cli.mjs`.** Run `npm link` again in the clone once; from now on `dotagents update` does it when the entry file changes.
- **Codex and OpenCode are gone.** `install` no longer writes their global configuration, and the standards, skills and docs cover Claude Code only. `move-sessions` lost its `--tools` option.
- **Accounts are now profiles.** `dotagents account add/list/remove` became `dotagents profile add/list/remove`, and `accounts.json` became `profiles.json`; `install` and `update` move the file. A profile is the local folder; the account is the Claude sign-in it holds.
- **The machine state is checked when read.** A `workspaces.json` or `profiles.json` that isn't valid, or that a newer dotagents wrote, stops the command instead of being read as empty and overwritten.

### Added

- **Codex accounts, switched in place like Claude's** (ADR 0017): `dotagents profile add <name> --provider codex` adds a ChatGPT account, and `switch` and `switch --save` put its login in `~/.codex/auth.json` from a vault per account and side, under Codex's own lock, then restart Codex's daemon. `dotagents login <name>` signs one in through `codex login` in a temporary folder, never in `~/.codex`, where a sign-in would revoke the login before it. `profile list` shows and checks them, and the `start` API (now `apiVersion: 2`) lists them with their `provider`, after the Claude ones, and says which one is in each side's slot, per provider. `profiles.json` gets a `provider` field and goes to version 2 only while it holds a Codex profile. The expiry checks and `login --all` stay Claude's for now.
- **Live usage of the Codex profiles:** `dotagents usage`, `usage --refresh`, `usage --json` and the `start` API show each Codex profile's 5-hour and 7-day windows and plan, asked of the official `codex app-server` (`account/rateLimits/read`, over stdio) and never of chatgpt.com. The slot's profile is asked in the real `CODEX_HOME` every 5 minutes, the others in a temporary one with a copy of their vault login every 30 (a renewed copy goes back to the vault), with Claude's backoff; a login OpenAI refuses is recorded with a mark for the checks. `usage` groups the profiles by provider.
- **Configuration for Codex:** `install` writes `~/.codex/AGENTS.md` (the global instructions with the rules at the end, since Codex has no rules folder) and links the skills into `~/.agents/skills`, where Codex reads them, on each side that has Codex; an older generated `AGENTS.md` is replaced and one you wrote is backed up. `profile list` checks it, and `.codex/` is in the workspaces' git exclude again. The template `global/instructions.md` no longer says only Claude Code: change the first line of yours too, run `dotagents install` and commit.
- **Several accounts and the providers' terms,** in [docs/security.md](docs/security.md#several-accounts-and-the-providers-terms), the README and Getting started: one account is enough and a second one is optional, several are for one person's own seats, and the links to Anthropic's and OpenAI's terms.
- **`dotagents doctor`:** whether dotagents can work here and what to do when it can't, in plain words: this side's Node, whether this side sees the other one and dotagents runs there with a Node new enough, and every profile's login on both sides.
- **A security page,** [docs/security.md](docs/security.md): where the logins are and who can read them, what goes over the network (only to Anthropic, plus GitHub and npm for `update` and `skills add`), the local API's guards, the masked logs, and what dotagents never does.
- **MCP servers in the configuration:** `claude/mcp-servers.json` names, for each server, how to run it on each system (`wsl`, `win32`, `linux`, `darwin`), and `install` writes this system's ones into `mcpServers` in `~/.claude.json`, as `claude mcp add --scope user` would, leaving the servers it doesn't name alone.
- **`dotagents usage --spend`:** what 1% of each account's 5-hour and weekly windows costs, in dollars at the API's prices and in tokens, from a history of the % that the live usage now keeps (`<state>/usage/<profile>.history.jsonl`, no extra request) and the tokens in Claude Code's transcripts on both sides, each under the account its session ran as. It says how much of the rise had no spend here, and breaks the current windows' spend down by model and folder, with the prompt revisions' cost. The API prices now live in one place, `core/prices.ts`.
- **The workspace has a history of its own:** in the recommended layout, `init` (and `new`) make the workspace root a git repository with a `.gitignore` that lets only the agent files in, so the projects' repositories inside stay out without being named, and `.claude/settings.local.json` too. It never commits, adds a remote or pushes. `check` fails a root that isn't a repository yet (run `init` again) and one that tracks a project's files.
- **Logs in files:** `dotagents start` and the commands write to `core.log` in `<stateDir>/logs/` (`~/.config/dotagents/logs/`): when `start` begins and stops (pid, version, the Node that runs it), the errors with their stack, the reads of the API that fail, and the calls to the other side of the machine that fail, with the command and its output. A failure that repeats is written once. Tokens are masked before writing, and past 1 MB a file rolls over to `.1`. The format is in [docs/logs.md](docs/logs.md).
- **`dotagents logs`:** where the logs of both sides of the machine are, and the last 50 lines of each; `--side wsl` or `--side windows` for one side.
- **Prompt revision, off by default (`dotagents revision on`):** each message you send is proofread (spelling, punctuation, grammar, without rewriting), by the newest Sonnet at low effort, through the signed-in Claude account (about 3 s per message) or, with `--api`, through your own Anthropic API key. The revision shows in the chat under your message, reaches Claude next to your message, and is what the session archive keeps. `revision off` turns it off, and `revision` shows what the revisions cost, next to the account's usage, from a log of each one. `revision fix` proofreads the messages of past sessions that ran without it, and rewrites their archives. It adds `@anthropic-ai/sdk` as a dependency: run `npm install` after pulling.
- **Open source, MIT.** A personal configuration project, published for anyone to use, fork and adapt.
- **The panel switches one side or both:** each account has `WSL | both | Windows`; `POST /api/switch` takes `"side"`, and `POST /api/refresh` asks Anthropic now.

- **`dotagents switch`:** for one person with several seats, puts a profile's login in `~/.claude` (and `~/.claude.json`'s `oauthAccount`), on both sides of the machine, saving the previous one in a vault per profile and side (`~/.config/dotagents/vault/`, readable only by you); `--here` for one side, `--save` to keep a fresh `/login`. Always manual.
- **When each login expires:** `profile list` says until when each profile's saved login lasts, on both sides, warns a week ahead and fails once it has expired, so it is renewed calmly.
- **Workspace memory:** `init` points every Claude profile's auto memory for a workspace at `.artifacts/memory/` (`autoMemoryDirectory` in `.claude/settings.local.json`) and copies in what each profile had learned there before; `check` verifies the folder, the index and the notes left behind.
- **The VS Code extension:** the current account and its usage in the status bar, a click to switch, the panel in the side bar, and a daily look for a newer release to install. Built with `npm run package` in `surfaces/vscode/`.
- **The panel:** the page `start` serves is the panel, in the dotagents identity: every account with its animated avatar, the account in each side's slot, the bars with the projection, and the switch and Desktop buttons. `usage --json` gives each profile its `avatar` state. The Windows tray panel of an earlier version is gone, and `install` removes its launcher.
- **`start` for the panel:** on Windows it reads WSL only while WSL runs, never waking it, and counts the running sessions of the other side; `POST /api/switch` and `POST /api/desktop` switch to a profile and open its Desktop app.
- **`dotagents login`:** signs a profile in again on this side when its login runs out (every few weeks), keeping the new login in its vault and putting the previous account back; `--all` for every login running out within a week. `profile list` points to it.
- **The account in use first:** `usage`, its `--short` and `--json`, and `start` list the profile in this side's slot first.
- **Usage projection:** `usage` shows under every window with fresh data how much it will have used at the reset at the current pace (`~79% at reset`), or, when it would pass 100%, when it runs out (`at this pace, runs out 16:40`), in yellow; a window already at its limit has none. `usage --json` carries it as `projection`.
- **Skills that call other skills:** dotagents reads which skills a skill calls (the Skill tool with a quoted name, a link to `../name/SKILL.md`); `init` and `update --all` bring them along, and the ones they call (`--skills pixijs` installs its 25 `pixijs-*` skills), `skills` shows them, `skills add` stores them in the catalog as `requires`, and `check` warns about each one a workspace lacks.

- **`dotagents start`:** the dashboard's local server, on 127.0.0.1 with a token, and a first page with the usage of every profile, live (server-sent events); a Windows window reaches it in WSL at the same address.
- **`usage --refresh`:** asks Claude Code itself for each profile's usage (`claude -p "/usage"`), which refreshes the cache and renews the sign-in without spending quota or leaving a session; at most once every 3 minutes per profile.
- **WSL and Windows together:** `install` finds the other side of the machine and `usage` reads its caches too; the newer numbers of the same account win, and the profile says where they came from.
- **The same configuration in every profile.** On Windows, `install` no longer overwrites a settings copy that `/config` changed: it keeps it and says so, and `dotagents settings pull` brings the change into the repository. `claude/global-config.json` sets the `/config` options Claude Code keeps in `.claude.json` (`copyOnSelect`, `diffTool`…) in every profile. `profile list` warns about a profile that differs and about changes to these files not committed yet.
- **The dotagents brand:** the symbol (the face `..`), its states and the lockup in `assets/`; the README opens with them and a capture of `usage`, drawn by `npm run media` from the same lines the command prints.
- **Profiles:** several Claude sign-ins on one machine, each with its config folder, the same configuration and a `claude-<name>` launcher (`profile add`, `profile list`, `profile remove`). `profile list` fails when two profiles hold the same account.
- **`dotagents usage`:** how much of each profile's plan is used (5-hour session, week, per-model weeks), from Claude Code's own cache, with no network. `--short` for one line, `--json` for scripts, `--watch` for the live view.
- **The full-screen view:** `dotagents` with no command, in a terminal, opens Usage, Profiles, Workspaces and Skills screens, with install and apply actions after a preview.
- **Claude Desktop per profile on Windows:** a Start menu shortcut "Claude <Name>" with the profile's icon, a second app with its own data folder, its own taskbar button, and the profile's window title, window icon and tray icon.
- **`update` runs `npm link` again** when a pull changes the command's entry file.

### Changed

- **Nothing personal in the tool:** the examples, the tests, the `session-archive` skill and the README's diagrams name the profiles `work` and `personal`, and the README's note about being a personal project is gone; the personal configuration lives in `dotagents-config`.
- **The settings are a copy on every system.** `~/.claude/settings.json` was a link to the repository's file on Linux and macOS, so `/model`, `/effort` and `/auto-mode-setup` changed the repository on every use; `install` now copies it there too, as on Windows, and turns an old link into a copy. `model`, `modelSettings`, `effortLevel` and `autoMode` are the machine's: a change in them is not a change, `install` keeps the copy's and `settings pull` doesn't take them.
- **Session archives with the user's messages proofread:** the archive shows each user message proofread (spelling, punctuation, grammar, without rewriting), as the [prompt revision](docs/commands.md#dotagents-revision) hook leaves it in the transcript; the replies stay verbatim. The `session-archive` skill (7.0.0) only runs the script and answers with the file's path, so it spends next to no tokens. For a message the hook didn't revise, the script takes revisions from `<name>.revisions.json` next to the archive, which `--prompts` lists the pending messages for and `--revise <file>` fills in; `sessions rm` keeps them.
- **The look follows the new identity** (Vercel's Geist palette, no accent): colors per background (`DOTAGENTS_THEME=light|dark`, else `COLORFGBG`, else dark), a profile's name in a readable variant of its color, exact 256 and 16 color mapping.
- **Every command prints without the rail** (`┌ │ ◇ └`): the ` dotagents ` badge in reverse video and the command, bold section titles, one line per item, a summary without `·`. Warnings show `▲`, skipped items `–`. Command names in the help are bold, not cyan. The prompts drop their rail too.
- **`usage` has a new layout:** no rail or dots, `5h`/`7d` labels, a thin bar of constant width, the percentage in bold, levels at 70% and 90% (were 50% and 80%), durations like `3h 17m`.
- Subagents run on Sonnet by default (`CLAUDE_CODE_SUBAGENT_MODEL` in the shared settings).
- The terminal output goes through one renderer, and each command lives in its own file.

### Fixed

- **The live usage says it is dotagents:** the requests to Anthropic's usage and token endpoints sent Claude Code's User-Agent, which the Usage Policy of 2026-11-12 forbids ("misrepresent the product or client being used"); they now send `dotagents/<version>`. The endpoint had also started answering Claude Code's User-Agent with 429 for these requests, so the live usage works again.
- **`sessions` and `sessions rm` now see title-only transcripts:** Claude Code leaves a stub with just a title (no message, no folder) when a session opens and closes empty. The list dropped it for lacking a folder, so `sessions rm` never deleted it and `/resume` kept showing it. It is now listed under the folder its project is named after.
- **Switching or listing sessions from Windows works with Node from nvm in WSL:** Windows ran `dotagents` in WSL through a login shell, which skips `~/.bashrc`, so nvm's Node wasn't on the PATH and an older system Node failed on the `.ts` sources. It now uses an interactive login shell (`bash -lic`), and a failure there shows Node's error line, not its version trailer.
- An unknown option (`check --bogus`) or command, or an option without its value, prints one line and exits with 2, instead of a stack trace or being ignored; `--` ends the options.
- `FORCE_COLOR=0` turns colors off instead of on, and `TERM=dumb` turns them off too. `FORCE_COLOR=1`, `2` and `3` set how many colors the output uses.

### Removed

- **Other agents' files in the exclude list:** `init` no longer lists `opencode.json`, `.codex/`, `.opencode/`, `.copilot/`, `.cursor/` and `.gemini/` in a repository's `.git/info/exclude`; dotagents is for Anthropic's products only. Run `dotagents update --all` to rewrite the block in the workspaces that have one.
