# Use case: an Obsidian vault

A vault of notes in [Obsidian](https://obsidian.md), worked on with Claude Code: the agents read and write notes, keep a task board, summarize slides, follow the vault's conventions. This page shows how to set the vault up as a dotagents workspace and what to watch out for.

## What makes a vault different

- **The vault folder can't move.** Obsidian, its sync and every device that opens the vault expect it at one path, so the [recommended layout](../workspaces.md#recommended-layout-the-workspace-wraps-the-repositories), a workspace that wraps the project, doesn't fit. The vault itself is the workspace.
- **Obsidian ignores dot folders.** `.agents/`, `.artifacts/` and `.claude/` don't show up in the file explorer, the search or the graph, so the agent files never mix with the notes.
- **It is usually synced by a cloud drive** (Google Drive, Dropbox, OneDrive, iCloud) or by Obsidian Sync, sometimes by git. Each one handles links differently, which decides what you need to do on a second machine (see [Sync](#sync)).

## Setup

On each machine where you use agents in the vault, after the [machine setup](../getting-started.md):

```bash
dotagents init ~/Notes --skills obsidian-docs
```

- `obsidian-docs` answers questions about Obsidian from the official help, the plugin directory and the forum. Add others you use, such as `humanizer` for writing or `session-archive` for transcripts.
- **When the vault is not a git repository** (a cloud drive or Obsidian Sync), there is nothing to exclude, and `init` asks nothing about the layout.
- **When the vault is a git repository** (the obsidian-git plugin, or git by hand), `init` offers to move it into `Notes-workspace/`. Answer **no**: the vault stays where it is, and the agent files are kept out of git through `.git/info/exclude`, without touching the vault's `.gitignore`. See [When the folder has to be the repository](../workspaces.md#when-the-folder-has-to-be-the-repository).

The result, next to the notes:

```
Notes/
├── AGENTS.md              how the agents should treat this vault (you write it)
├── skills-lock.json       third-party skills, if any
├── .agents/skills/        obsidian-docs → <clone>/skills/obsidian-docs, …
├── .claude/               skills → .agents/skills, settings.json
├── .artifacts/            INDEX.md, plans/, session-archives/
├── .obsidian/             Obsidian's own settings
└── <your folders and notes>
```

Run the agents from the vault root. Check the setup at any time with `dotagents check ~/Notes`.

## Write the AGENTS.md

`init` creates `AGENTS.md` from a template; replace it with what an agent needs to *do* in this vault. Keep it short and written by you: a context file generated by an agent and accepted without review tends to make results worse, not better (see [Evaluating AGENTS.md](https://www.sri.inf.ethz.ch/publications/gloaguen2026agentsmd)). What usually belongs there:

```markdown
# Notes

One sentence: what the vault holds.

## Sync

- How the vault is synced, and what the agent must never touch because of it
  (the drive's temporary folders, a git plugin that must stay off, …).
- That links don't travel with the sync, if that is the case, and the command
  that recreates them.

## Structure

- What each top-level folder holds.
- Where tasks, daily notes or a board live, and the frontmatter they use
  (`status: To Do`, …).

## Note conventions

- Language, and how files are named (plain text with spaces, numbered lecture notes…).
- Internal links as wikilinks (`[[Note]]`), also to PDFs with a page:
  `[[file.pdf#page=4|p.4]]`.
- Callouts, math, tags: whatever the vault uses.
- Files the agent must not edit as text (Excalidraw drawings, canvases).
- When renaming or moving a note, update the wikilinks that point to it.

## Obsidian

- The plugins the vault relies on (Dataview, Tasks, Templater…), so the agent
  writes notes they understand.
- Edit files in `.obsidian/` only with Obsidian closed: while it runs, it
  overwrites them.
```

## Sync

What a sync carries depends on whether it copies links:

| In the vault | Real files or links | With a cloud drive | With git (+ `.git/info/exclude`) |
|---|---|---|---|
| `AGENTS.md`, `.artifacts/`, `.claude/settings.json` | files | synced | **not** synced (excluded) |
| Third-party skills in `.agents/skills/`, `skills-lock.json` | folders and files | synced | not synced |
| Own skills in `.agents/skills/`, `.claude/skills` | links to the dotagents clone | **not** synced: most drives skip links (Google Drive skips Windows junctions) | not synced |

- **With a cloud drive,** run `dotagents init <vault> --skills …` once on each machine: it recreates the links and leaves the synced files as they are. Write that command in `AGENTS.md`, so you (or an agent) find it on a new machine.
- **With git,** nothing of the agent setup travels with the vault: run `init` on each machine, and keep anything worth sharing (plans, transcripts) in a place that does travel.
- **Don't combine a drive and git sync** on the same vault: the two fight over the same files.

## Day to day

- **Ask about Obsidian itself** (a plugin, a Bases view, a setting): `obsidian-docs` looks it up in the official sources instead of guessing.
- **Keep a record:** `session-archive` writes the session to `.artifacts/session-archives/`, which a cloud drive syncs with the vault.
- **Plans** from Claude Code's plan mode land in `.artifacts/plans/`.
- **After changing your own skills** in the dotagents clone, nothing needs to run: the vault links to them.

## Pitfalls

- **The agent edits `.obsidian/` while Obsidian is open,** and Obsidian writes its old state back. Close Obsidian first, or let the agent only suggest the change.
- **Renames break links.** Obsidian updates wikilinks when *it* renames a note; an agent renaming a file from the shell doesn't. The rule in `AGENTS.md` covers it.
- **Drive housekeeping files** (`.tmp.drivedownload/`, `.tmp.driveupload/`, `desktop.ini` on Windows) look like vault content to an agent. List them in `AGENTS.md` as off-limits.
- **A copied skill instead of a link** (for example after restoring the vault from a backup that resolved the links): `dotagents check` reports it; delete the copy and run `init` again.
